### КРИТИЧНО: бесконечный цикл перестройки UI (по жалобе "навигация/скролл/лаги")

Пользователь: не работали выбор пресетов и вообще вся навигация, скролл
отбрасывало наверх, смена настроек сильно пролагивала.

- **Причина:** в Fyne v2.8.1 `widget.Select.SetSelected` вызывает
  `updateSelected`, который **дёргает `OnChanged`** (проверено по исходникам
  модуля: `widget/select.go`). В `gui/settings.go` при каждой сборке UI
  вызывался `langSelect.SetSelected(...)` → `OnChanged` → `i18n.SetLocale` →
  `onLocaleChange` → `rebuildUI` → снова `SetSelected` → **бесконечный цикл**
  перестройки контента. Это вешало UI-поток: навигация не реагировала, скролл
  сбрасывало, смена настроек "пролагивала".
- **Исправление:**
  1. `i18n.Manager.SetLocale` теперь уведомляет слушателей только при реальной
     смене языка (`m.current == code` → выход), что разрывает цикл.
  2. `SettingsPanel` получил флаг `updating`; программная инициализация
     `themeSelect.SetSelected`/`langSelect.SetSelected` выполняется с
     `updating = true`, а обработчики при этом выходят сразу.
  3. `buildMainMenu` оборачивает программный `presetSelect.SetSelected` в
     `a.syncing`, чтобы не запускать `OnChanged` при построении меню.
- **Проверка:** после фикса exe в простое даёт `CPU=0 мс` за 3 с (до фикса был бы
  постоянный пересчёт UI). Добавлен регрессионный тест
  `TestI18nSetLocaleOnlyFiresOnChange` (тестов стало 18).
- **Пресеты на диске не подхватывались:** `AppConfig.ListPresets` не вызывался,
  поэтому пресет-файлы, отсутствующие в `ActivePresets` (напр. после копирования
  или старой версии), не отображались. Добавлен `AppConfig.SyncPresets`
  (объединяет файлы из `presets/` с `ActivePresets`), вызывается в `main.go`
  после загрузки конфига; добавлен тест `TestSyncPresetsDiscoversFiles`
  (тестов стало 19).

### КРИТИЧНО: звук "сдыхает" и "ломается" (по жалобе + инструментальная диагностика)

Пользователь: при тесте звук не транслируется, драйвер "сдыхает", приложение
"тупо ломается". Диагностика выполнена реальным пробником PortAudio на машине
(`go run -tags portaudio`), т.к. изображение со скриншотом недоступно модели.

Обнаружены **две критические причины**, обе воспроизведены и исправлены:

1. **Смешение host API при выборе устройства.** PortAudio на Windows отдаёт 19
   устройств из 4 разных API (MME, DirectSound, WASAPI, WDM-KS) с
   дублирующимися именами; у MME имена обрезаны до 31 символа. Прежний
   `resolveDevice` выбирал первый совпадающий по имени - часто это оказывалось
   WDM-KS (kernel-streaming, эксклюзивный режим), из-за чего устройство
   "залипало"/драйвер отваливался. Теперь перечисление и выбор ограничены
   **одним host API - тем же, что у системного устройства по умолчанию**
   (`preferredHostAPI`), с дедупликацией имён. Список стал: 2 входа / 3 выхода
   (MME) вместо 19.

2. **PortAudio не переинициализировался после Stop.** Refcount `Initialize`
   был в конструкторах устройств, а `Terminate` - в `Close`. После первого
   `Stop()` библиотека завершалась, а повторный `Open()` (Start) уже не звал
   `Initialize()` → ошибка **"no input device: PortAudio not initialized"**.
   Это и есть "ломается": Toggle Вкл→Выкл→Вкл переставал работать. Теперь
   `Initialize`/refcount живут в `Open` (`ensurePortAudioInit`), релиз - в
   `Close` (`releasePortAudio`); добавлен флаг `paInit`, чтобы `Terminate`
   вызывался строго один раз и только после реальной инициализации.
   Пробником подтверждён цикл Start→Stop→Start→Stop.

Проверки после фикса: `gofmt`/`go vet`(±`-tags portaudio`) чисто,
`go test -race ./tests/` - 22 OK, exe пересобран (25.27 МБ), APK пересобран
(121 МБ), Android arm64 компилируется, пробник реального пайплайна:
recapture → эффекты → playback, Start/Stop/restart OK.


### Проход по жалобе "багается проверка звука + не работает система пресетов"

Инструментальная диагностика (пробники, чтение реального `config.json` и
файлов пресетов в `%APPDATA%\SimpleVoiceChanger`).

**Проверка звука (Test Voice) - рваный/щелкающий тон.** `Engine.PlayTest`
заполнял буфер и после каждого блока спал `bufferSize/sampleRate` (`time.Sleep`).
На Windows гранулярность таймера ~15 мс, а интервал блока при 1024 сэмплах -
~21 мс: реальный сон уезжал до ~31 мс, буфер (4 блока) пустел, PortAudio-колбэк
писал нули - отсюда "багается"/треск. Исправлено: `PortAudioPlayback` теперь
отдаёт `Buffered()` (уровень заполнения), а `PlayTest` держит очередь в 1-3
блока (low/high-water) и ждёт разгрузки, а не "спит вслепую"; добавлен сторож
на зависание (10 с). Пробник: `PlayTest` x3 - по ~1.7 с, без ошибок и залипаний.

**Система пресетов не работала (визуально).** Выбор пресета в выпадающем
списке и в списке вкладки только помечал `SelectedPreset`, но НЕ применял
эффекты - приходилось отдельно жать "Загрузить". Теперь выбор в любом месте
UI сразу применяет пресет (`App.loadPresetInto`: двигает движок, конфиг,
слайдеры, сохраняет выбор). Дополнительно: сохранение пишет ВСЕ 15 эффектов
(раньше только те, что были в карте - отсюда пресеты с 6 ключами), а
`SyncFromConfig` сбрасывает слайдеры всех эффектов, а не только присутствующих
в файле - значит загрузка пресета полностью переопределяет состояние.

Проверки после прохода: `gofmt` чисто, `go vet ./...` и `go vet -tags portaudio
./...` чисто, `go test -count=1 ./tests/` - 22 OK, `go build ./...` и

## 🔴 КРИТИЧЕСКИЕ

### ЛОГИКА И БАГИ

**1. [Баг] Повторный Start после Stop сломан, двойной Stop - panic**
- **Где:** `audio/engine.go:115-127`, `audio/engine.go:93-112`
- **Описание:** `stopCh` создаётся один раз в `NewEngine` и закрывается в `Stop()`. При повторном `Start()` канал уже закрыт, `runLoop` сразу выходит через `select <-e.stopCh`. При повторном `Stop()` после нового `Start()` (stopped сброшен) - `close(e.stopCh)` на закрытом канале → **panic: close of closed channel**.
- **Последствия:** GUI Toggle Вкл→Выкл→Вкл роняет приложение; после первого выключения движок больше не запускается.
- **Решение:** пересоздавать `stopCh`/`doneCh` в `Start()`, а в `Stop()` не закрывать закрытый канал.

**2. [Баг] Двойной portaudio.Initialize/Terminate**
- **Где:** `audio/portaudio.go:27-31`, `audio/portaudio.go:157-161`, `audio/portaudio.go:140`, `audio/portaudio.go:268`
- **Описание:** Capture и Playback каждый вызывают `portaudio.Initialize()` в конструкторах и `Terminate()` в Close. Повторный `Pa_Initialize` возвращает ошибку → `factory_desktop.go` падает в fallback на mock.
- **Последствия:** в сборке `-tags portaudio` один из двух бэкендов всегда мок (тишина/нет захвата).
- **Решение:** общий счётчик refcount init/term в портаудио-бэкенде.

**3. [Баг] `PortAudioCapture.Open` не сбрасывает closed**
- **Где:** `audio/portaudio.go:43-49` (vs `:185` у Playback)
- **Описание:** Playback сбрасывает `closed=0` в Open, Capture - нет. После первого Close повторный Open вернёт "capture already closed".
- **Последствия:** повторный запуск захвата невозможен даже после фикса №1.
- **Решение:** сбросить `closed=0` в `Open`.

**4. [Баг] Ключ `effect_strength_format` не переводится**
- **Где:** `i18n/manager.go:92-97`, `i18n/manager.go:151-163`, `gui/effects.go:107`
- **Описание:** `formatKeys` перемещает `effect_strength_format` из `Data` в `Formats`, но `translate()` ищет только в `Data`. `t("effect_strength_format", ...)` вернёт сам ключ.
- **Последствия:** ВСЕ слайдеры эффектов показывают "effect_strength_format" вместо "Эффект: 50%".
- **Решение:** в `translate()` проверять `Formats` тоже.

**5. [Безопасность] Path traversal в имени пресета**
- **Где:** `core/config.go:130-175`, `gui/preset.go:139`, `gui/preset.go:172`
- **Описание:** `name` берётся из ввода и из импортируемого JSON без санитизации, `filepath.Join(presetsDir, name+".json")` → `../` выводит за пределы каталога. `deletePreset` - `os.Remove`.
- **Последствия:** запись/чтение/удаление произвольных файлов, XSS-like через импорт.
- **Решение:** валидация имени (только безопасные символы, `filepath.Base`, запрет `..`).

**6. [Баг] Тема сломана на не-английских локалях**
- **Где:** `gui/settings.go:33-38`, `gui/settings.go:87-99`
- **Описание:** `themeOptions = [t("dark"), t("light")]` (переведено), а `themeCodeToLabel` возвращает "Dark"/"Light" (англ.). `SetSelected("Dark")` не находит "Тёмная"; `themeLabelToCode("Светлая")` → "dark".
- **Последствия:** на русском и др. селект темы пуст, светлая тема не выбирается.
- **Решение:** работать с кодами напрямую, label только для отображения.

**7. [Баг] LowCut - фильтр низких частот вместо high-pass**
- **Где:** `effects/low_cut.go:31`
- **Описание:** `filtered := state + alpha*(s-state)` - это low-pass. "Low Cut" должен удалять НИЗКИЕ (high-pass): `y = s - filtered`. `high_cut.go` - корректный low-pass.
- **Последствия:** эффект режет все высокие вместо нижних, голос превращается в бубнение.
- **Решение:** high-pass: `samples[i] = (1-mix)*s + mix*(s-filtered)`.

**8. [UI/UX] `importPreset`/`exportPreset` в главном меню - заглушки**
- **Где:** `gui/app.go:249-279`
- **Описание:** диалоги открываются, но файл не читается/не пишется - сразу "import_success"/"export_success". Рабочие версии - в `gui/preset.go:154-215`.
- **Последствия:** фиктивный импорт/экспорт из главного меню.
- **Решение:** делегировать в пресет-панель или убрать из меню.

## Дополнительный проход: нестабильные DSP-эффекты (№26) + имена устройств

### Проблема «периодический пик/звук багается» - КОРЕНЬ НАЙДЕН И ИСПРАВЛЕН

**Диагностика.** Прогон всех 15 эффектов на чистом 2-секундном синусе (0.3 ампл.,
чанки 512) через DSP-пробник показал взрывы при силу `strength`:

| Эффект | 18 | 50 | 100 |
|--------|-----|-----|-----|
| reverb | +Inf (BLOW) | +Inf (BLOW) | +Inf (BLOW) |
| chorus | 2e21…2e28 (BLOW) | BLOW | BLOW |
| formant | 3.4 | 22 | 82 |
| radio | 12 | 34 | 69 |
| harmony | 4.9 | 35 | 141 |
| low_cut | 4.8 | 14.6 | 29.6 |
| compressor | 15 | - | - |
| flanger | 17 | - | - |

Пре-сет пользователя `antinoise=23, chorus=18` давал в chorus пиковые
`1.9e19` - именно это слышно как периодический «пик/багается».

**Причины.**
- `strength` в слайдерах/конфиге = 0…100, а DSP трактовал её как 0…1
  (`mix := strength*0.5` → при 18 уже 9) - возможны усиления в десятки раз.
- Chorus читал сэмплы из обрабатываемого буфера → само-обратная связь → рост 2e28.
- Reverb `fb=0.5*strength` > 1 → +Inf.
- Phaser `alpha=f*0.1*strength` > 1; Radio пропорциональный state ~1.95×/сэмпл;
  Formant квадратичное состояние → 82; Harmony/Radio/LowCut усиление ×десятки.
- Compressor усиливал (makeup при max > 1.6), а не сжимал.

**Исправлено (переписывание `effects/*.go`, все 12 эффектов).**
- Единая нормализация `norm := strength/100`, все mix ≤ 0.8, коэффициенты < 1.
- Chorus: настоящая линия задержки (прошлый сухой сэмпл, LFO 10–18мс), без
  self-feedback.
- Reverb: 4 задержки, `fb = 0.35*norm`.
- Formant: стабильный каскад one-pole (s1/s2), `mix = 0.7*norm`.
- Harmony: 2 линии задержки с детюном, `mix = 0.5*norm`.
- Radio: bounded state (`s*0.5 + state*0.92`), клиппинг ≤ 1, `mix = 0.8*norm`.
- Flanger/Phaser/Doubler: нормализованный mix (≤ 0.6), alpha 0.12–0.9.
- LowCut/HighCut: one-pole `alpha = 1/(2π f T + 1)`, НЕ усиливают.
- Compressor: порог/ratio с мягкой огибающей, makeup ≤ 1.4 - сжимает.
- AntiNoise: ворота `threshold = √var * (0.9+1.2*norm)`, тон 0.3 проходит.

**Проверка DSP-пробником** - все 15 эффектов на 18/50/100 стабильны:
максимумы в диапазоне 0.07…1.01, NaN/Inf/BLOW отсутствуют (было 7 взрывов).
